# 知识可视化与研究地图方案调研

> 调研日期：2026-08-01
>
> 目的：寻找适用于科研论文、技术 Roadmap 和原创分析内容的知识可视化方案，并为本知识库的交互化改造提供设计与技术依据。

## 结论概览

现有方案大致分为三类：

1. **文献关系发现工具**：擅长引用、共引、相似论文和局部邻域探索；
2. **科学知识图谱平台**：擅长把研究问题、方法、结果和贡献结构化；
3. **科学计量与主题地图工具**：擅长聚类、主题演化、时间线和矩阵分析。

没有一个轻量开源项目同时提供“人工 Roadmap、逐篇原创分析、主要贡献判断、证据边界和多视图交互”。更合理的方案是组合成熟设计模式，而不是完整复制某个平台。

推荐借鉴关系：

- ORKG：贡献级语义；
- Open Knowledge Maps / Head Start：主题地图入口；
- Connected Papers / Citation Gecko：局部邻域探索；
- Paperscape：缩放层级与时间约束布局；
- bibliometrix：矩阵和主题演化；
- Scholia：同一实体的多视角详情页；
- Cytoscape.js + D3：实现交互视图；
- Observable Framework：静态内容发布和数据加载。

## 关键区分

需要严格区分三类关系：

| 关系 | 含义 | 自动化程度 |
|---|---|---|
| Citation | A 引用了 B | 可以从开放文献数据库获取 |
| Similarity | A 与 B 在文本、嵌入或共引结构中相近 | 可以近似计算 |
| Contribution | A 对某个技术问题提出了什么主要新主张 | 需要人工判断和复核 |

引用和相似度可以帮助发现论文，但不能替代主要贡献判断。

## 代表方案

### Open Research Knowledge Graph

项目：

- [ORKG Frontend](https://github.com/TIBHannover/orkg-frontend)
- [ORKG Backend](https://github.com/TIBHannover/orkg-backend)
- [ORKG 文档](https://docs.orkg.org/)

ORKG 是语义定位最接近本项目目标的系统。它将 Research Contribution 作为核心实体，并将贡献与 Research Problem、Method、Result 等结构连接起来，支持跨论文比较。

可借鉴：

- 将贡献从论文正文中拆为机器可读实体；
- 使用模板约束同类论文的可比较字段；
- 贡献比较比单纯 citation graph 更适合综述与技术路线。

不建议直接采用完整 ORKG 技术栈。其后端、图数据库、关系数据库、API 和在线编辑能力对于约 150 篇人工策展论文过重。更适合采用精简的 ORKG-like YAML Schema，并保留未来导出能力。

### Open Knowledge Maps / Head Start

项目：

- [Head Start](https://github.com/OpenKnowledgeMaps/Headstart)
- [Open Knowledge Maps](https://openknowledgemaps.org/)

Head Start 将文献自动聚类为带标签的主题区域，为不熟悉领域的读者提供地图式入口。其价值不在于论文节点本身，而在于先展示主题区域，再允许用户进入局部内容。

可借鉴：

- Roadmap 首页展示技术区域而不是论文毛线球；
- 主题区、列表和详情面板联动；
- 支持搜索、筛选、缩放和局部展开。

局限：自动主题聚类无法区分主要贡献和论文中采用的普通组件，也可能与人工技术路线冲突。因此本项目应固定人工 Roadmap，只将自动相似度用于技术点内部排序和遗漏候选发现。

### Connected Papers

产品：[Connected Papers](https://www.connectedpapers.com/about)

Connected Papers 使用共引和 bibliographic coupling 构建论文相似图，而非简单绘制直接引用树。它围绕种子论文展示局部邻域，并区分 Prior Works 和 Derivative Works。

可借鉴：

- 以局部视图替代全局大图；
- 选中论文后突出相似路径；
- 将先导工作和后续工作分开；
- 图视图与论文列表并存。

局限：核心产品不是可直接 fork 的开源实现，也不能回答论文的关键贡献是什么。

### Citation Gecko

项目：[Citation Gecko](https://github.com/CitationGecko/gecko-react)

Citation Gecko 从 seed papers 出发扩展 cited / cited-by 邻域，并允许用户逐步把相关论文加入工作集。

可借鉴的交互流程：

1. 选择一个技术点或论文；
2. 展示局部邻域；
3. 将感兴趣的邻居加入当前工作集；
4. 基于新工作集继续扩展；
5. 在表格和图之间切换。

本项目可将“种子论文扩展”改为“技术点扩展”，默认只展开 Primary / Secondary Contribution 和语义明确的研究继承边。

### Paperscape

项目：[Paperscape Backend](https://github.com/paperscape/paperscape-backend)

Paperscape 将 arXiv 论文绘制成类似地理地图的知识空间，通过缩放级别控制节点和标签密度。它证明大型研究地图可以采用地形和瓦片式体验，而不一定是普通力导向图。

可借鉴：

- 多级缩放和标签密度控制；
- 领域全景与局部邻域分离；
- 研究路线图使用时间约束，而非完全自由布局。

不建议复用其旧后端代码和基础设施。应借鉴布局思想：时间作为固定轴，技术家族作为另一轴，节点表示技术点、贡献和论文。

### VOSviewer Online

项目：[VOSviewer Online](https://github.com/neesjanvaneck/VOSviewer-Online)

VOSviewer Online 支持 citation、co-authorship 和 co-occurrence 等网络，并可通过 iframe 或 React component 嵌入页面。

优势：

- 集成快；
- 具备成熟的缩放、筛选、标签和分享能力；
- JSON 网络格式简单。

局限：其数据模型面向网络展示，不适合承载贡献声明、证据边界、Primary / Secondary 等领域语义。可作为附加 Network View，不应成为主数据模型。

### bibliometrix / Biblioshiny

项目：

- [bibliometrix](https://github.com/massimoaria/bibliometrix)
- [Bibliometrix 官网](https://www.bibliometrix.org/)

bibliometrix 提供完整的科学计量和 science mapping 工作流，包括共引、bibliographic coupling、关键词共现、主题图、主题演化和 historiograph。

最值得借鉴的是：

- Paper × Contribution Matrix；
- 主题演化 Sankey；
- 年度时间线；
- 通过矩阵而不是大图比较同期论文。

不建议直接把 R Shiny 应用嵌入主站。可以用 D3、Observable Plot 或普通虚拟表格复现关键视图。

### Scholia

项目：

- [Scholia](https://github.com/WDscholia/scholia)
- [Scholia 服务](https://scholia.toolforge.org/)

Scholia 基于 Wikidata 和 SPARQL，为论文、作者、组织、主题和期刊生成不同的 profile 页面，包括时间线、合作网络、引用关系和主题统计。

可借鉴：

- 每个实体拥有独立详情页；
- 同一数据通过多个 aspect 呈现；
- 外部 ID、来源和多语言标签作为长期互操作基础。

不建议在 MVP 中把 Wikidata 作为唯一数据源。可以在本地实体中增加 OpenAlex、Semantic Scholar 和 Wikidata ID，再按需生成类似 Scholia 的页面。

### SurVis

项目：[SurVis](https://github.com/fabian-beck/survis)

SurVis 是面向综述、论文和学位工作的可视化文献浏览器，支持标签、搜索、时间分布和关系分析。它比普通 awesome list 更接近“策展数据 + 交互浏览”。

可借鉴：

- 适合小到中等规模人工策展数据；
- 多字段筛选和详情视图；
- 可将文献列表作为静态站点发布。

局限：主要实体仍然是论文和标签，缺少贡献声明层。

## 可视化与交互框架

### Cytoscape.js

文档：[Cytoscape.js](https://js.cytoscape.org/)

适合承担局部图的状态管理和交互，支持 compound nodes、图遍历、DAG 和约束布局。当前规模预计低于一千个核心节点，不需要优先选择 WebGL 大图引擎。

### D3

项目：[D3](https://github.com/d3/d3)

适合实现时间线、矩阵、Sankey、滚动叙事和高度定制的过渡动画。不建议用 D3 从零重写完整图编辑器和图状态管理。

### Observable Framework

文档：[Observable Framework](https://observablehq.com/framework/)

支持在 Markdown 中嵌入响应式 JavaScript，并使用 JavaScript、Python、R 或 Shell 的 data loader 在构建时生成静态数据。适合 GitHub Pages 和无需服务端的知识站点。

### Sigma.js

文档：[Sigma.js](https://www.sigmajs.org/docs/)

适合数千到数万节点的 WebGL 图。若未来把 OpenAlex 邻域、作者和组织全部展开，可用于全局 Overview；当前 MVP 使用 Cytoscape.js 更简单。

## Storytelling 参考

### Distill 风格交互文章

Distill 风格适合通过局部交互、逐步揭示和可操控示例解释复杂概念，但制作成本高。应建立可复用模板，并只覆盖少量核心主题。

### 3Blue1Brown / Manim

项目：[Manim](https://github.com/3b1b/manim)

Manim 适合程序化解释动画和视频传播，不适合作为浏览器内知识管理框架。推荐让视频与交互网站共享同一结构化数据，而不是把 Manim 直接嵌入主站。

### Scrollytelling

滚动叙事适合回答“为什么研究路线从 A 演进到 B”。每个滚动步骤控制同一张图的局部状态，避免反复切换页面。它适合作为专题入口，而非全部论文的默认浏览方式。

## 对本项目的建议

### 不建议

- 将全部论文直接放入一张力导向图；
- 以 citation count 作为贡献重要性的主要指标；
- 让 embedding 聚类覆盖现有六条技术路线；
- 第一阶段部署完整 ORKG 或 Neo4j 平台；
- 自动抽取结果未经人工确认就写入 Primary Contribution；
- 为全部论文制作独立动画。

### 建议

1. 先定义 Contribution Schema，再实现图；
2. Roadmap 作为固定入口，局部技术点按需展开；
3. 将 Primary Contribution 限制为一个；
4. 将矩阵视图设为研究比较的核心；
5. 使用外部 API 补充元数据，而不是决定领域判断；
6. 保留现有 Markdown 长文，增加独立结构化层；
7. 第一批只标注 20–30 篇 Motion Tracking / Sim2Real 论文；
8. 使用 GitHub PR 完成标注和复核。

## 数据来源建议

- [OpenAlex Works API](https://developers.openalex.org/api-reference/works)：开放 ID、出版信息、引用关系和开放获取状态；
- [Semantic Scholar Academic Graph API](https://www.semanticscholar.org/product/api)：论文、引用、推荐和部分语义字段；
- 论文原文和官方项目页：贡献判断和证据边界的最终依据。

外部 API 只负责元数据和候选关系。技术点、主要贡献、局限和继承关系必须保留人工复核记录。
